## 0. 🔴 最初に読むこと —— ストアに並ぶ前に告知すると詰む

承認直後のバイナリは**地域ごとに段階的に配信される**。数時間は古い版が返る。
そこで「更新してください」と出すと、**押しても更新できない**。
必須更新にしていた場合、**アプリが使えなくなる**。

| ☐ | 守ること |
|:-:|---|
| ☐ | 🔴 `latest_version` を上げるのは、**実機でストアから実際に落とせることを確認した後** |
| ☐ | 🔴 `min_supported_version` は**既定で空**。入れるのは「その版ではデータが壊れる」ときだけ |
| ☐ | ⚠️ 審査中は `min_supported_version` に**審査対象の版を含めない**（reviewer が古い版で詰む） |
| ☐ | 🔵 事故ったら `is_enabled` を OFF にすれば **60 秒**で全ユーザーから消える |

## 0.5 運用早見表（admin の 3 つの設定）

| `is_enabled` | 最新バージョン | 最低サポートバージョン | 何が出るか |
|:---:|---|---|---|
| **OFF** | 何でも | 何でも | 🔵 **何も出ない** |
| ON | 空 | 空 | 何も出ない |
| ON | `1.1.4` | 空 | `1.1.4` 未満に**推奨更新**（「後で」で 24 時間消える） |
| ON | 空 | `1.1.4` | `1.1.4` 未満に**必須更新**（閉じられない） |
| ON | `1.1.6` | `1.1.4` | `1.1.4` 未満は必須、`1.1.4`〜`1.1.5` は推奨 |

🔴 **事故ったら `is_enabled` を OFF にする。** 60 秒で全ユーザーから消える
（推奨も必須もまとめて止まる）。

⚠️ **文面を書いてもしきい値が空なら誰にも出ない。** 必須更新の文面を
用意しただけでは発火しない ——「最低サポートバージョン」に数字を入れて初めて出る。

## 1. しきい値 2 本の意味

| field | 意味 | 画面 |
|---|---|---|
| `latest_version` | 「ここまで上げてほしい」 | 「後で」で閉じられる |
| `min_supported_version` | 「ここより古いと使わせられない」 | **閉じられない** |

⚠️ **両方を同時に使うとユーザーが 3 群に分かれる。**
例: `latest=1.1.6` / `min=1.1.4`

| 端末の版 | 出る画面 |
|---|---|
| 1.1.3 以下 | 閉じられない（必須更新） |
| 1.1.4 / 1.1.5 | 閉じられる（推奨更新） |
| 1.1.6 | 出ない |

🔵 **文面は 2 組に分かれている。** 1 組で共用すると
**どちらかの群に必ず嘘が出る**ので、そうしていない。

🔵 **【FEAT-544 (2026-09-23)】必須更新の文面も admin で編集できる。**
既定値が日英そろって入っているので、**緊急時に書くものは無い**。
⚠️ 空にするとアプリ内の既定文が出るので、**文面の無い画面にはならない**。

## 2. 通常のリリースで告知する手順

```
1. App Store の審査が通る
2. ⏳ 実機で「App Store → Sabiowl → 更新」が押せることを確認する
     🔴 ここを飛ばさない。段階配信で数時間は古い版が返る
3. admin → バージョンアップ告知設定
     latest_version に新しい版を入れる（例: 1.1.4）
     min_supported_version は 空のまま
     日本語 / English の文面を確認（既定のままでよい）
     is_enabled を ON
4. 保存する（cache は保存で即座に落ちる）
5. 実機で告知が出ることを確認する
```

⚠️ **手順 3 の文面は既定のままで構わない。** 版ごとに言い方を変えたいときだけ
編集する。英語欄が空なら、英語のユーザーには
`api/models/app_update.py` の `EN_FALLBACK` が出る（日本語は出ない）。
🔵 **英文の真実値は model 側の 1 箇所だけ**で、view はそれを import している。

---

## 3. 🔴 必須更新を出す手順（データが壊れるときだけ）

```
1. 「その版ではデータが壊れる」ことを確認する
     ⚠️ 「新機能を使ってほしい」は理由にならない。推奨更新で足りる
2. 🔴 修正版がストアに並び、実機で落とせることを確認する
     これを飛ばすと、ユーザーは「更新してください」と言われたまま更新できない
3. min_supported_version に「これ未満は使わせない」版を入れる
     ⚠️ 審査中の版を含めない
4. is_enabled が ON であることを確認して保存
5. 実機で「後で」が無い画面が出ることを確認する
```

🔴 **必須更新は閉じられない。** 間違えて広い範囲を指定すると、
**その範囲のユーザーがアプリを一切使えなくなる**。
逃げ道は `is_enabled` の OFF だけである。

---

## 4. 事故ったとき

```
admin → バージョンアップ告知設定 → is_enabled を OFF → 保存
```

🔵 **60 秒で全ユーザーから消える。** cache の TTL が 60 秒で、
保存時に明示的に落としているためである。

⚠️ **アプリの再起動は要らない。** 告知は起動時に 1 回聞くので、
既に開いている端末では次回起動まで残る。
🔴 **必須更新で締め出している場合、ユーザーはアプリを再起動できる**ので、
OFF にすれば次の起動で通常 UI に戻る。

## 5. 誰に届くか、届かないか

| 端末の版 | 届くか |
|---|---|
| 🔴 **FEAT-543 より前の版** | ⛔ **届かない。** 告知を出すコードが入っていない |
| FEAT-543 を含む版で `latest_version` 未満 | ✅ 推奨更新 |
| `min_supported_version` 未満 | ✅ 必須更新 |
| `latest_version` 以上 | 🔵 何も出ない |

🔴 **この機能は「入った版から先」にしか効かない。**
**「全ユーザーに今すぐ告知できる機能」だと誤解しないこと。**
それより古い版に留まっている人は、別の理由で更新したときに初めて対象になる。

⚠️ **「古い版が何人いるか」は測れない。** サーバは各ユーザーがどの版を
使っているかを知らない（送っているのは `Accept-Language` と `Authorization`
だけ）。必要になったら先に `X-App-Version` ヘッダーを足すこと（別 FEAT）。

## 6. 出ないときに見るところ

| 症状 | 見るところ |
|---|---|
| 何も出ない | `is_enabled` が ON か / `latest_version` が端末の版より**新しい**か |
| 版を入れたのに出ない | `latest_version` の形。**`x.y.z` ちょうど**でないと無視される（`1.1` / `v1.1.4` は読めない） |
| 一度出たあと出ない | 「後で」を押すと**その版について 24 時間**出ない。版を上げれば即座に出る |
| 英語端末に日本語が出る | `*_en` が空なら `EN_FALLBACK` が出るはず。**日本語が出ているなら実装の不具合** |
| 必須更新の文面を書いたのに出ない | **「最低サポートバージョン」が空**。数字を入れて初めて発火する |
| 必須更新の文面を空にした | アプリ内の既定文が出る。**無文面にはならない** |
| 保存したのに変わらない | cache は保存で落ちるが、gunicorn の worker ごとに独立している。最大 60 秒待つ |

🔵 **推奨更新の 24 時間抑制は端末の `SharedPreferences` にある。**
アプリを入れ直すと消える（秘密ではないので secure storage には置いていない）。
