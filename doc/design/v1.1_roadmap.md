**FEAT-367 Phase 1 スコープ (v1.1 採択)**:

- 共通 widget `SabiVoiceInputButton` 新規 (~150 LOC、TextField suffix 形式でマイクアイコン)

- STT 結果を **名前/タイトル/メモ フィールドのみ自動入力** (構造化フィールド = カテゴリ/頻度/難易度/日時 は既存 UI 維持)
- 録音 UI: 波形プレビュー + 30 秒タイマー + 「使う / やり直し / キャンセル」3 ボタン
- プライバシーポリシー追記 (OS 内蔵 STT を使用、Sabiowl は録音保存しない、Apple/Google サーバ経由認識)

**🔴 SEC-11 との関係 (整合性宣言)**:
SEC-11 (2026-05-15、commit `74bd150`) で `speech_to_text` パッケージは **SabiNavigate (LLM 対話型ナビゲーション) コスト撲滅** のために削除されました (Anthropic 月次数千〜数万円、CLAUDE.md「月 3 万円ガードレール」違反)。FEAT-367 はこれと **用途が完全に異なる**:
- ✅ FEAT-367 採用範囲: **OS 内蔵 STT のみ** (iOS Speech Framework / Android SpeechRecognizer、無料、ネット接続必要だが Apple/Google サーバとユーザー端末の通信、Sabiowl Backend 経由なし)
- ❌ FEAT-367 不採用範囲: LLM 経由のテキスト解釈 (Anthropic / OpenAI / Gemini 等、Phase 3 で課金導入時に再評価)
- → SEC-11 哲学「LLM コスト撲滅」は完全維持、pubspec.yaml への speech_to_text 単独再導入のみが SEC-11 状態からの変更点

**Pre-mortem 6 件**:
1. SEC-11 哲学崩壊リスク → 指示書 §1 で「STT only、LLM 経由テキスト解釈ゼロ」明文化
2. OS 内蔵 STT 精度ばらつき (日本語の習慣カテゴリ「精神」「貢献」等が誤認識) → 名前/タイトルのみ採用、構造化フィールドは UI 維持
3. マイク許可拒否で永久使用不可 → 拒否時サビ口調 SnackBar「設定 → アプリ権限から有効化できますよ 🪶」
4. iOS Apple 制限 (最大 1 分 / 同時 1 / ネット必要) → 30 秒タイマー + offline UI 隠す
5. 既存 UI 混雑 → TextField suffix にマイクアイコン (省スペース)
6. プライバシーポリシー追記必須 → privacy_policy_page 第 13 条 (音声認識の取扱) 新規追加

**v1.2 候補 (Phase 2、~3-5 日)**: Keyword matching parser で構造化フィールド推定 (「毎日朝 7 時にジョギング」→ frequency='daily' / name='ジョギング' / due_time='07:00')。LLM 不要、ルールベース。Phase 1 完了後 PostHog で利用率観察してから投資判断。
